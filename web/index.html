Using the Calculator

Click on numbers and functions in Calculator just as you would with a standard calculator.
The display shows the equation as you enter it, so you always see the operation to be carried out. Click the equation sign and the display shows the result, with the finished equation on the small line above it. The opened parenthesis button keeps a ring around it until all parentheses expressions are closed.

If an equation gets too long for the display, its font gets smaller first. After that, hold the line and drag it left or right to see the rest; dots (…) mark the side where more is hidden.
If a calculation is not possible (for example 1 ÷ 0), the display shows Error and the line above shows the equation that caused it.

This calculator uses an algebraic method of entry that allows you to enter mathematical sequences in the same order that they are algebraically stated (PEMDAS / AOS™).
PEMDAS: "Parentheses, Exponents, Multiplication or Division, and Addition or Subtraction". Multiplication and division have the same ranking. Addition and subtraction as well.

Keyboard Support

There is full keyboard support for each button on the calculator.

  • The numbers and + – × ÷ , . = keys can also be input on number block.
  • See below the keyboard shortcuts of each calculator button in [brackets].
  • Use the [Backspace] key or the DEL button to take back the last key you pressed: a digit, an operator, a bracket or a function. A finished result stays.
  • Hold key: [h, s] means: press h or H and you'll see a little 'hold' in the right bottom corner of the display.
    This makes the followed key function different: [s] = sin, but [h, s] = sinh, etc.
  • Copy/Paste from/to display with Ctrl+C and Ctrl+V. Ctrl+C copies the result or, while you are still entering an equation, the equation as text.
    Ctrl+V pastes a number (1,234.5 and 1.234,5 are both read as 1234.5) or a whole equation, such as 2 + 3 × sin(30) or sqrt(16) + 2^3. If the pasted text contains an equation sign, it is calculated right away.
    Right-click anywhere on the calculator for a menu with Copy and Paste as well. Copy takes the part of the display you selected, or else the result. The first time you use Paste there, your browser may ask you to allow reading what you copied; Ctrl+V works without that.
  • All [ENTER] keys represent the '=' button.
  • Click Rad or Deg at the bottom left of the display to switch between them.
  • [←] and [→] move the cursor in the equation, like the buttons. [Home] and [End] go to its start and its end.
  • History: click the clock at the top left of the display to see the calculations you finished with '='. Point at an equation or a result to show its two buttons on the left: insert enters the equation again, so you can change it or finish it with '=', or puts the result in as a number in the equation you are entering; copy copies it. A calculation with sin, cos or tan is marked with the unit it was done in, Deg or Rad, and is worked out in that unit again. A calculation done in fraction mode keeps its fractions, and one done with decimals keeps its decimals; inserting it switches fraction mode to match.

About Precision

This calculator operates with a precision of about 15 significant digits (only). This is due to how JavaScript handles floating point numbers.
This isn't actually a JavaScript feature but a feature of the way the IEEE 754 standard defines how floating point numbers are stored in memory. JavaScript requires every number to be one of these 64-bit values, and any language that uses them, such as C, Java or Python, suffers from this 'feature' too.

Results are shown with 13 significant digits, so these tiny rounding errors stay out of sight: 0.1 + 0.2 shows 0.3, not 0.30000000000000004. Angles in degrees give exact values where they should: sin 180 is 0 and cos 60 is 0.5.

The problem is that JavaScript uses 64 bits of data, which can hold 18446744073709551616 different bit patterns, to store every number: 1 bit for the sign, 11 bits for the exponent and 52 bits for the digits. That covers values from about –1.7976931348623157e+308 to 1.7976931348623157e+308, with the smallest normal number at 2.2250738585072014e–308 and even smaller ones down to 5e–324.
A smaller precision value with some of the bits as an exponent is how it fits that range (this can also be done in 16 bits with a smaller range and less precision). The result is that it can approximate any value in the range but not exactly represent them all, because in real number terms there are an infinite number of values between any 2 given values.
As part of your calculation clearly the internal representation of the value is going outside the available precision and you are ending up with an approximation to the value instead of an exact value.
